## 2-1. 기존 자산 (재사용 대상)

`C:\Users\rokaf\OneDrive\바탕 화면\PLC monitoring_01\plc-monitoring ver1.0 - google\`에 이미 동작하는 Node.js 프로젝트가 있음.

> ⚠️ **기준 경로 정정(2026-08-26)**: 이전에는 `plc-monitoring ver1.0\`(google 접미사 없음)을 기준으로 삼았으나, 사용자 확인 결과 **`plc-monitoring ver1.0 - google\`가 통신 연결부의 최신 버전**임. FINS 클라이언트 파일 자체(`tcpFinsClient.js` 등)는 두 폴더가 동일하지만, `server.js`·`gmsManager.js` 등 나머지 코드와 의존성 버전(`better-sqlite3` 13.x 등)은 `- google` 쪽이 더 최신.

> 🔀 **재사용 방식 변경(2026-08-26, QA_LOG Q-018)**: 처음엔 "이 코드를 기반으로 확장"할 계획이었으나, 사용자 결정에 따라 **완전 독립된 신규 프로젝트**로 방향을 바꿈. 기존 GMS 앱(`server.js` 등)은 **전혀 수정하지 않고**, 아래 표의 통신 관련 파일만 **복사**해서 이 프로젝트 전용 서버를 새로 구성한다. 기존 GMS 앱은 이미 `PLC monitoring_01\backup\plc-monitoring ver1.0 - google_BACKUP_2026-08-26\`로 백업 완료. PC(GMS)와 모바일을 함께 쓰는 통합은 **향후 별도 프로젝트**로 진행.

원본 폴더(`plc-monitoring ver1.0 - google\`)에서 **복사해서 가져올** 파일:

| 항목 | 원본 위치 | 비고 |
|---|---|---|
| FINS 통신 클라이언트 | `src/tcpFinsClient.js`, `udpFinsClient.js` | Omron CJ2H 대상, TCP/UDP 지원 — **복사**해서 이 프로젝트 전용 서버에 포함 (USB는 로컬망 시나리오에 불필요) |
| FINS 프로토콜 처리 | `src/finsCommands.js`, `memoryAreas.js`, `dataTypes.js` | 명령어/메모리영역/데이터타입 — `usbFinsClient.js`의 일부 상수(`AREA_CODES` 등)도 함께 필요하므로 해당 파일도 복사 |
| 서버 참고 | `src/server.js` | 그대로 가져오지 않고, Express+WebSocket 뼈대 구조만 **참고**해서 이 프로젝트 전용으로 새로 작성 (인증/RBAC/AuditLog가 처음부터 포함된 구조) |
| 이력 저장 | GMS 원본은 `better-sqlite3`(^13.0.3) | 이 프로젝트는 Node 내장 `node:sqlite`로 채택(better-sqlite3 아님) — 이유는 §2-2 및 QA_LOG Q-023 참고 |
| 프론트엔드 | — | 기존 `public/*.html`은 데스크톱 GMS 화면이라 참고만 하고, 모바일 PWA는 새로 작성 |
| Windows 배포 | — | 이번 프로젝트는 모바일이 PWA로 접속하는 구조라 기존 `installer/` 방식은 해당 없음 (서버 실행 방식은 Design 단계에서 별도 결정) |

기존 GMS 프로젝트는 **전혀 수정하지 않음** — 코드는 복사본만 사용하고 원본은 백업된 상태로 그대로 둔다.

모든 의존성(`express`, `ws`, `node:sqlite` 등)은 **무료 오픈소스(npm 패키지)** — 유료 라이선스 없음. §3-2 "무료/오픈소스 원칙" 참고.

기타 관련 폴더(미조사, 필요시 확인): `plc-monitoring ver1.0`(구버전, google 변형으로 대체됨), `plc-monitoring-usb`, `Program_Review_Tool_v1.0`, `backup`

## 2-2. 개발 도구/비용 원칙 — 무료(오픈소스) 우선

앞으로 이 프로젝트에서 새로 도입하는 프로그램/라이브러리/툴은 **무료(오픈소스 또는 무료 티어)를 우선 사용**한다. 유료 도구가 꼭 필요하면 사용 전 반드시 사용자에게 확인받는다.

현재까지 결정된 스택의 비용 점검:

| 항목 | 선택 | 비용 |
|---|---|---|
| 백엔드 런타임 | Node.js | 무료 |
| 백엔드 라이브러리 | 이 프로젝트: express, ws, bcrypt, node:sqlite(Node 내장). 참고한 GMS 원본: express, ws, better-sqlite3, exceljs, pdfkit, usb, xlsx, dependency-cruiser | 전부 무료 오픈소스(npm) 또는 Node 내장 |
| 개발 환경(IDE) | VSCode | 무료 |
| 프론트엔드 | 순수 HTML/CSS/JS + PWA | 무료 (프레임워크 라이선스 없음) |
| 모바일 배포 | PWA (앱스토어/플레이스토어 배포 없음) | Apple 개발자 계정($99/년), Google Play 등록비($25) **모두 불필요** |
| 디자인 툴 | 코드 기반 목업(`bkit:phase-3-mockup`) | 무료 — Figma 등 유료 플랜 불필요 |
| 데이터베이스 | node:sqlite(파일 기반 내장 DB) | 무료, 별도 DB 서버 비용 없음 |

→ 현재까지의 선택은 전부 무료 원칙에 부합함. Design/Do 단계에서 새 라이브러리·서비스(예: 클라우드 호스팅, 지도 API 등)가 필요해지면 이 원칙에 따라 무료 옵션을 먼저 검토한다.

## 3. 안전/보안 관련 주의사항 (설계 단계에서 반드시 반영)

- Omron FINS 프로토콜은 **자체 인증 기능이 없음** → 브릿지 서버 단에서 반드시 별도의 인증/인가 계층을 둘 것
  (로컬망이라도 전면 제어이므로 비밀번호/토큰 기반 로그인 필수)
- 전면 제어 특성상 **오조작 방지 장치** 필요 (예: 위험 명령 2단계 확인, 조작 이력 로깅, 동시 접속 제어)
- 로컬 와이파이 한정이지만, 향후 외부 원격 접속 확장을 고려해 아키텍처는 VPN/터널링 확장 가능하게 설계
- 브릿지 서버 ↔ PLC 구간과 모바일 ↔ 브릿지 서버 구간의 보안 수준을 분리해서 검토
