# 모바일 화면 포팅 계획 — 기존 PC(GMS) 화면 → 휴대폰/PDA 반응형

> **작성일**: 2026-08-28 (QA_LOG Q-027)
> **목적**: 기존 PC 프로그램 `plc-monitoring ver1.0 - google/public/`의 화면을 **하나씩** 휴대폰·PDA 해상도에 맞게 다시 디자인해 이 프로젝트(`Claude/`)의 모바일 PWA로 옮긴다.

## 2. 현재 모바일 PWA 상태 (기준선)

`Claude/public/` 에 이미 구현됨:

- **로그인 화면** (`#login-view`) — 세션 기반 인증
- **대시보드** (`#app-view`) — 태그 검색 / 페이지네이션 / 값 표시 + **위험명령 2단계 확인 모달**
- PWA 요소: `manifest.json`(standalone), `service-worker.js`(정적 캐시만)

→ 대시보드는 S2(메모리 모니터링)의 축소판에 해당. 포팅 작업은 이 기준선을 **확장**하고 나머지 화면을 **추가**하는 것.

## 4. 공통 반응형 기준 (모든 화면 적용)

- 기준 뷰포트: 세로 **360–430px 폭**(휴대폰), 가로 **768–1024px**(PDA/태블릿)까지 대응
- 터치 타깃 최소 44×44px, 위험 버튼(쓰기/조작)은 색상+아이콘+2단계 확인
- 표는 좁은 화면에서 카드형으로 전환하거나 가로 스크롤 컨테이너로 감쌈(본문 가로 스크롤 금지)
- PC 전용 상호작용(마우스 hover, 우클릭)에 의존하지 않음
- 오래된 PLC 값 캐시 금지(design.md §6) — 항상 서버 최신값

## 4-1. Plan B — 단일 태그 실시간 값 (2026-08-28)

매핑표 도착 전, 값이 실제로 움직이는 것을 폰에서 확인하기 위한 최소 백엔드:

- `GET /api/tags/:id/value` — 주소 배정된 태그 1개를 매 요청마다 PLC에서 워드 읽기(캐시 없음). `data_type`(UINT16/INT16/WORD) 해석, `bit_index` 있으면 워드에서 비트 추출.
- `PATCH /api/tags/:id/address` (ADMIN) — 개별 태그에 `area_type`/`address`/`bit_index` 직접 배정·해제. 매핑표 도착 시 대량 Import로 대체될 임시 수단.
- S2 모니터링 탭: 탭 활성 동안 3초 주기로 주소 배정된 태그 값 폴링, 카드에 표시. ADMIN은 카드의 주소 라벨을 눌러 배정 모달.
- `src/plcRead.js` 신규. `finsShared.js` AREA_CODES에 `A`(Auxiliary, 읽기전용 시스템영역=0xB3) 추가.
- 검증: 실제 PLC `D0 = 7473`(고정값), `A351`(내부 시계 워드, 매 초 변함) 읽기 성공. 읽기 전용 태그만 주소 배정 — 라이브 안전 PLC라 쓰기 태그엔 주소 미배정.
- S2에 "갱신 HH:MM:SS" 폴링 시각 표시 + 값 셀 깜빡임(값이 같아도 갱신 확인 가능).
- 대량(약 2,000개) 배치 폴링은 매핑표 도착 후 별도 구현(design.md §7).
