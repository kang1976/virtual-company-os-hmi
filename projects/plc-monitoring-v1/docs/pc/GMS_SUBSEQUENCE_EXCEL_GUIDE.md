# GMS 서브시퀀스(자동진행) 엑셀 사용 가이드

이 문서는 조정모드 등 "자동진행" 서브시퀀스를 정의하는 엑셀 파일(예: `AdjustMode_v1.xlsx`)을
어떻게 편집해야 하는지 설명합니다. 실행 엔진은 `public/gms-sub-sequence-runner.js`, 엑셀
내보내기/불러오기는 `src/server.js`(`/api/gms/sub-sequences/:id/export/xlsx`,
`/api/gms/sub-sequences/import/xlsx`)가 담당합니다.

## 0. 서브시퀀스 목록 한눈에 보기

`data/gmsSubSequences/`에 있는 파일(id)과 실제 화면·진입 순서 대응표입니다. 실린더 교환
자동진행 흐름을 순서대로 따라간 것으로, 대부분은 이전 단계가 끝나면 **자동으로** 다음
화면으로 넘어갑니다(버튼을 눌러 직접 들어가는 게 아님 - 상단 CYLINDER STEP STATUS 배지를
클릭하는 "Status Jump"로 건너뛸 수는 있습니다).

각 화면의 "서브시퀀스 엑셀 내보내기/불러오기" 버튼은 그 화면의 **대기(idle) 상태**에
있습니다(대부분 "실행" 버튼과 같은 자리). CylReplace_v1만 예외로, 진입화면
("용기교체CC_실린더 확인")에 항상 떠 있는 버튼입니다.

## 1. 어디서 내려받고 어떻게 다시 반영하나

조정모드 화면(보조 메뉴 → 조정모드 A/B) 대기 상태에서:

- **서브시퀀스 엑셀 내보내기** - 지금 서버에 저장된 시퀀스를 그대로 `.xlsx`로 내려받습니다.
- **서브시퀀스 엑셀 불러오기** - 편집한 파일을 선택하면 **서버가 즉시 파일까지 저장**합니다.
  화면에서 따로 "저장" 버튼을 누를 필요가 없습니다. 시트 이름이 그대로 서브시퀀스 id가 됩니다
  (예: 시트 이름 `AdjustMode_v1` → 그 id로 저장).

## 2. 엑셀 파일 구조 (4행 헤더)

실제 엔지니어링 문서 양식을 그대로 따릅니다.

| 행 | 내용 |
|---|---|
| 1행 | 제목(전체 열 병합) |
| 2행 | 그룹 헤더 - `STEP` / `TIMING / CONDITION` / `VALVE (O=Open, C=Close, 공백=이전 상태 유지)` / `ALARM / REMARKS` |
| 3행 | 단위 힌트 - Time(Sec)/Acc,Time(Sec) 위에 `Sec` |
| 4행 | **실제 열 이름** - 불러오기가 이 행의 텍스트로 열을 인식합니다. 열 순서를 바꿔도 되고, 필요 없는 밸브 열은 지워도 됩니다 - 헤더 텍스트만 정확하면 됩니다. |
| 5행부터 | 데이터. `S/No.`가 빈 행은 통째로 건너뜁니다. |

## 3. 열 설명

### 고정 열 (A~L, "STEP"/"TIMING·CONDITION" 그룹)

| 열 | 헤더 | 내부 필드명 | 설명 |
|---|---|---|---|
| A | `S/No.` | `no` | Step 번호(문자열). 반드시 있어야 하고, `Next Step`/`Ack Goto`/`Alarm Goto`가 이 값으로 점프 대상을 찾습니다. 정수가 아니어도 됩니다(`"7A"`처럼 중간에 끼워 넣을 때 씀). |
| B | `Main Step` | `mainStep` | 화면 표시용 대분류 번호. |
| C | `Sub Step` | `subStep` | 화면 표시용 소분류 번호. |
| D | `Next Step` | `nextStep` | **조건이 참일 때** 다음 줄이 아니라 이 Step No로 곧장 이동. 비어 있으면 평소처럼 다음 줄로 진행(하위호환). |
| E | `Operations` | `operation` | Step 설명 문구(화면 상단에 표시). **비어 있으면 이전 Step의 문구를 그대로 유지**합니다(값이 있는 Step에서만 갱신). |
| F | `Cycle` | `cycle` | 현재 엔진에서 쓰이지 않습니다(예전 반복문 표기용 임시 규칙 - `nextStep`+`Alarm Goto`+조건식 조합으로 대체됨). 자유롭게 메모용으로 써도 됩니다. |
| G | `진행방식` | `advance` | `자동`(빈 값도 자동) 또는 `확인`/`확인대기`/`수동`/`ACK` - "확인"류 값을 적으면 그 Step은 타이머 없이 조작자가 화면의 "확인" 버튼을 눌러야 다음으로 넘어갑니다. |
| H | `Ack Goto` | `ackGoto` | `advance`가 자동이든 확인이든, 다음 Step으로 넘어갈 때 다음 줄이 아니라 이 Step No로 이동(조건과 무관하게 항상). |
| I | `Alarm Goto` | `alarmGoto` | **조건이 거짓일 때** 이동할 Step No. 채워져 있으면 `Alarm Seq.`의 원래 동작(초기화/이어서재진행/SHUTDOWN, 밸브 CLOSE 포함) 대신 **밸브 상태·누적시간을 그대로 둔 채 가볍게 그 Step으로만 이동**합니다(반복문·분기처럼 "알람이 아닌" 용도로 Alarm Seq. 체계를 재사용할 때 씀). 비어 있으면 지금까지처럼 `Alarm Seq.` 코드가 그대로 실행됩니다. |
| J | `Message at Controller` | `message` | 조작자에게 보여줄 안내 문구. **비어 있으면 이전 Step의 메시지를 그대로 유지**합니다(Operations 열과 같은 규칙). |
| K | `Time (Sec)` | `timeSec` | 이 Step에서 대기할 시간(초). 비어 있거나 0이면 바로 다음으로. |
| L | `Acc,Time (Sec)` | `accTimeSec` | **자동 합계 수식**(`=SUM($K$5:K행번호)`) - 손으로 입력하지 않습니다. Time(Sec) 값을 바꾸거나 행을 추가/삭제해도 엑셀이 알아서 다시 계산합니다. 실행 엔진은 이 값을 참고용으로만 두고(표시 안 함) 실제 진행에는 쓰지 않습니다 - 실제 경과시간은 실행 중 화면의 "누적 경과시간"이 별도로 실시간 계산합니다. |

### 밸브 열 (M열부터, "VALVE" 그룹)

서브시퀀스마다 정해진 밸브 태그 목록(`valveTags`) 순서대로, **열 이름 자체가 밸브 태그명**입니다.
셀 값은 `O`(Open) / `C`(Close) / 빈 칸(이전 상태 유지) 셋 중 하나만 씁니다. 태그에 `{side}`가
포함돼 있으면(예: `FPV_{side}`) 실행 시 진행 중인 측(A/B)으로 자동 치환됩니다.

### 조건/알람 열 ("ALARM / REMARKS" 그룹, 밸브 열 다음)

| 열 | 헤더 | 내부 필드명 | 설명 |
|---|---|---|---|
| - | `Alarm Monitoring` | `alarmMonitoring` | 감시할 태그(또는 예약어) - 아래 4장 참고. |
| - | `비교연산자` | `conditionOp` | `<`, `>`, `<=`, `>=`, `==`(또는 `=`), 또는 bit용 `ON`/`OFF`. 끝에 `?`를 붙이면 "옵션"(4-3장 참고). |
| - | `설정명(비교대상ID)` | `conditionValue` | 비교할 값 - CONFIG 탭의 설정명 또는 id, 또는 숫자 리터럴(ON/OFF 연산자면 안 씀, `-` 같은 자리표시자만 채움). |
| - | `조기통과` | `earlyPass` | `Y`/`예`/`O` 등을 채우면, Time(Sec) 대기 중 매초 조건을 다시 확인해서 참이 되는 즉시(남은 시간을 기다리지 않고) 다음으로 넘어갑니다. |
| - | `Alarm Seq.` | `alarmSeq` | 조건이 거짓이고 `Alarm Goto`가 비어 있을 때 실행할 코드 - `1`=초기화(밸브 전체 CLOSE 후 처음부터), `2`=이어서재진행(멈춘 Step 기억, 다음 "실행" 때 이어감), `3`=SHUTDOWN(초기화 후 메인 화면 이동). **비어 있으면 "에러사항" 화면에 기록되지 않습니다**(6장 참고). |
| - | `Alarm Message` | `alarmMessage` | 알람 발생 시 남길 메시지(작업이력/에러사항에 기록됨). |
| - | `Remarks` | `remarks` | 자유 메모. 조건식이 복잡한 Step은 여기에 사용법을 적어두는 것을 권장합니다(아래 예시 참고). |

## 4. 조건식(Alarm Monitoring / 비교연산자 / 설정명) 사용법

### 4-1. 기본형

```
Alarm Monitoring: VPT
비교연산자:        <=
설정명(비교대상ID): 진공하한치_A
```
→ 실행 중 VPT의 실시간 값이 CONFIG 탭 "진공하한치_A" 값 이하이면 참(정상 진행), 아니면 거짓
(Alarm Seq./Alarm Goto 발동).

### 4-2. `{side}` 템플릿

태그와 설정명 둘 다 `{side}`를 쓸 수 있고, 실행 시 진행 중인 측(A/B)으로 치환됩니다.

```
Alarm Monitoring: HPT_{side}
설정명(비교대상ID): 진공하한치_{side}
```
→ A측 실행이면 `HPT_A`를 CONFIG "진공하한치_A"와 비교, B측이면 `HPT_B` vs "진공하한치_B".
같은 한 줄로 양쪽 측에 그대로 씁니다.

### 4-3. 다중 조건 (AND, `&`로 구분)

세 열 전부 `&`로 같은 개수만큼 나눠 적으면 AND로 묶입니다(실제 문서의 "SPT & DPT" 관례와 동일).

```
Alarm Monitoring: VPT & LPT_{side} & HPT_{side} & NPT_{side} & MPT_{side}?
비교연산자:        <= & <= & <= & <= & <=?
설정명(비교대상ID): 진공하한치_{side} & 진공하한치_{side} & 진공하한치_{side} & 진공하한치_{side} & 진공하한치_{side}
```
(실제 예시: Step 7) 전부 참이어야 정상 진행, 하나라도 거짓이면 그 즉시 거짓입니다. **세 열의 `&`
개수가 서로 안 맞으면** 콘솔 경고 + 화면 토스트로 바로 알려줍니다(오타 방지).

### 4-4. 옵션 마커 `?`

연산자 끝에 `?`를 붙이면(`<=?`, `ON?`) 그 항목은 "옵션"입니다 - 그 태그의 실시간 값을 아직
모르면(센서가 없거나 아직 값이 안 들어옴) **그 항목 하나만 건너뛰고 나머지는 그대로 평가**합니다.
전부 옵션이고 전부 스킵되면 "조건 없음"(항상 통과)으로 취급합니다. **CONFIG에서 값을 못 찾는
것(오타)은 옵션 여부와 무관하게 항상 경고**합니다 - "센서가 없다"가 아니라 "설정을 잘못
적었다"는 뜻이라 조용히 넘어가면 안 되기 때문입니다.

### 4-5. BIT ON/OFF

연산자를 `ON` 또는 `OFF`로 쓰면 아날로그 값이 아니라 밸브 등 bit 신호의 실제 개폐 상태(fb)를
봅니다. 이때 `설정명(비교대상ID)` 칸은 값을 안 쓰지만, `&`로 여러 조건을 묶을 때 열 개수를
맞추기 위해 `-` 같은 자리표시자를 채워야 합니다(비워두면 개수가 안 맞아 경고가 뜸).

### 4-6. 예약 태그 (실제 센서가 아닌 값)

`Alarm Monitoring`에 아래 이름을 그대로 적으면 PLC 값이 아니라 프로그램 내부 상태와 비교합니다.

| 예약어 | 비교 대상 | 연산자 | 용도 |
|---|---|---|---|
| `진행횟수` | 이 실행의 Cycle 반복 진행 횟수(1부터 시작) | 비교 연산자(`<`,`>=` 등) | 반복문 종료 조건(5장 참고) |
| `조정모드시퀀스1` | OPTION 탭의 "조정모드 시퀀스 1" 스위치(적용/미적용) | `ON`/`OFF`만 | Option 기반 분기(5장 참고) |
| `Bypass사용` | OPTION 탭의 "Bypass 사용 옵션" 스위치 | `ON`/`OFF`만 | `AfterPlusL_v1` Step 2 |
| `고압HELeakCheck` | OPTION 탭의 "고압 HE Leak check 라인 유무" 스위치 | `ON`/`OFF`만 | `Bypass_v1` Step 25 |
| `가압시험후PulsVent` | OPTION 탭의 "가압시험 완료후 Puls Vent" 스위치 | `ON`/`OFF`만 | `AfterPlusL_v1` Step 15 |

OPTION 스위치 예약어는 `public/gms-sub-sequence-runner.js`의 `SUB_SEQ_OPTION_TAGS`에 등록된
이름만 쓸 수 있습니다 - 새 스위치가 필요하면 개발자가 그 표에 한 줄 추가해야 합니다.

### 4-10. `ZERO` (비교연산자) - 압력조정 표 자동 0점 조정

조건을 평가하는 게 아니라, **그 Step에 도달하는 순간 압력조정(캘리브레이션) 표의 offset을
자동으로 다시 계산**하는 액션입니다(참/거짓 판정 없음 - `Alarm Seq.`/`Alarm Goto`와는 무관).

```
Alarm Monitoring: NPT_{side} & HPT_{side} & MPT_{side} & LPT_{side} & VPT
비교연산자:        ZERO & ZERO & ZERO & ZERO & ZERO
```
(실제 예시: `AdjustMode_v1` Step 36) → 각 태그의 압력조정 표 "현재값"이 정확히 0이 되도록
offset을 즉시 재계산해서 저장합니다. 비교대상(`설정명(비교대상ID)`) 칸은 쓰지 않습니다. 끝에
`?`를 붙이면(`ZERO?`) 그 태그가 압력조정 표에 없어도 조용히 건너뜁니다. 보통 바로 다음 Step에서
`:OFFSET` 조건(4-8장)으로 같은 태그를 확인하면, 방금 반영된 새 offset이 곧바로 적용됩니다.

### 4-7. `CAPTURE:<태그>` (Cycle 열) - 초기값 캡처 + 실시간 안전감시

Pumping(`OneP3`)/`-L`(`ExchL`)/`+L`(`AfterPlusL`)/VT(`VtTest`, `AfterVtTest`)/`Bypass`(`Bypass_v1` Step 19, `CAPTURE:NPT`)류가 쓰는
"60초 대기하며 초기값 대비 안전조건 실시간 감시" 패턴입니다.

```
Cycle: CAPTURE:NPT_{side} (또는 CAPTURE:HPT_{side})
Alarm Monitoring: NPT_{side}   비교연산자: <=   설정명(비교대상ID): 진공하한치_{side}
```

- 이 Step에 **처음** 도달했을 때 `HPT_{side}`의 현재값을 화면의 "초기값"란에 한 번만 저장하고,
  "현재값"란은 실행 중 계속 실시간 값으로 갱신됩니다.
- `Alarm Monitoring`/`비교연산자`/`설정명(비교대상ID)`에 적어둔 안전조건은 `Time (Sec)` 타이머가
  다 찰 때까지 기다리지 않고, PT 값이 새로 들어올 때마다(약 1초 주기) 즉시 검사합니다 - 이상이면
  그 즉시 `Alarm Seq.`가 발동합니다(타이머 만료를 기다리지 않음).
- 보통 바로 다음 Step에 예약어 `진행횟수`(4-6장)로 "분 단위 시간이 다 찼는지" 판정을 두고,
  아직 안 찼으면 `Alarm Goto`로 이 Step으로 되돌아가 60초씩 반복합니다(ExchL_v1.json Step
  6/6A, 7/7A가 실제 예시).

### 4-8. `<태그>:OFFSET` - 압력조정(캘리브레이션) 현재값 기준 비교

```
Alarm Monitoring: NPT_{side}:OFFSET   비교연산자: <=   설정명(비교대상ID): NPT_{side}:MAX80%
```

PLC 원시값이 아니라 **압력조정 탭에서 계산된 "현재값"**(캘리브레이션 반영값)의 절댓값을 씁니다.
비교대상에 `<태그>:MAX<n>%`를 쓰면 그 태그의 압력조정 표 "Max값 × n%"를 목표값으로 씁니다
(숫자를 CONFIG에 미리 등록해둘 필요 없이 압력조정 표 기준으로 비율만 정하고 싶을 때).

### 4-9. `<태그>:CAPOFFSET` - 이번 실행에서 캡처한 초기값 기준 비교

`:OFFSET`의 자매 문법이지만, 비교 기준이 압력조정 표가 아니라 **이 Step의 `CAPTURE:<태그>`로
이번 실행에서 방금 저장해둔 초기값**입니다(누출시험처럼 "시작할 때 값 대비 얼마나 변했는지"를
볼 때 씀 - VT류가 사용).

```
Cycle: CAPTURE:VT_{side}
Alarm Monitoring: VT_{side}:CAPOFFSET   비교연산자: <   설정명(비교대상ID): VT 누출 압력 변동 기준_{side}
```
→ 목표값 = (초기값 + CONFIG 값). 비교대상 앞에 `-`를 붙이면(`-가압 시험-압력 변동 기준_A`처럼)
"초기값 − CONFIG 값"이 목표값이 됩니다(가압 시험처럼 "값이 내려가면 이상"인 방향일 때 씀).

## 5. 분기 제어: Next Step / Alarm Goto / Ack Goto 비교

| 열 | 언제 이동하나 | 밸브·상태는? |
|---|---|---|
| `Ack Goto` | `진행방식`이 "확인"류인 Step에서, 조건과 무관하게 다음으로 넘어갈 때 | 정상 진행(그대로) |
| `Next Step` | 조건이 **참**일 때 | 정상 진행(그대로) |
| `Alarm Goto` | 조건이 **거짓**일 때 | 그대로 유지한 채 가볍게 이동(밸브 CLOSE·초기화 없음) |
| (`Alarm Goto` 비어있고 조건 거짓) | `Alarm Seq.` 코드 1/2/3 실행 | 코드에 따라 밸브 CLOSE·초기화 발생 |

### 예시 A - Option 켜짐/꺼짐에 따라 다른 Step으로 (Step "7A")

Step 7(배관진공 5중 조건 확인)이 정상 통과된 뒤에만 도달하는, 밸브 변경 없는 순수 분기 Step:

```
S/No.: 7A            Next Step: 14         Alarm Goto: 8
Alarm Monitoring: 조정모드시퀀스1   비교연산자: ON   설정명(비교대상ID): -
```
→ OPTION 탭 "조정모드 시퀀스 1"이 **적용**이면 Step 14로, **미적용**이면 Step 8로(평소 다음
Step과 동일 번호라 사실상 "그냥 다음으로 진행"). 어느 쪽이든 알람이 아니라 정상적인 분기입니다.

### 예시 B - N회 반복 (Step "23")

```
S/No.: 23             Next Step: 24         Alarm Goto: 2
Alarm Monitoring: 진행횟수   비교연산자: >=   설정명(비교대상ID): 설정횟수
```
→ "진행횟수 >= 설정횟수(CONFIG 값)"가 참이면(반복 완료) Step 24로 진행. 거짓이면(아직 반복
중) Step 2로 되돌아가면서 진행횟수가 1 늘어납니다. 반복 횟수는 CONFIG 탭 "설정횟수" 행의
값을 바꾸면 됩니다(재실행부터 적용). 화면에는 "설정 횟수 / 진행 횟수"가 함께 표시됩니다.

## 6. "에러사항" 화면과의 관계

`Alarm Seq.` 열이 실제로 채워져 있고 `Alarm Goto`로 가볍게 이동하지 않은 경우(=진짜 초기화/
이어서재진행/SHUTDOWN이 실행된 경우)에만 보조 메뉴의 "에러사항" 화면(별도 DB - `error_log`
테이블)에 기록됩니다. **`Alarm Seq.`가 비어 있으면(반복문·Option 분기처럼 Alarm Goto만 쓰는
Step) 절대 기록되지 않습니다** - 실제 알람이 아니기 때문입니다.

## 7. CONFIG 탭과의 연결

`설정명(비교대상ID)` 칸은 CONFIG 탭(gms.html 상단 탭 바 "CONFIG.")의 **설정명 또는 ID** 둘
중 아무거나로 찾습니다. CONFIG 탭도 자체적으로 엑셀 내보내기/불러오기가 있고(불러오기는
서브시퀀스와 마찬가지로 즉시 저장), 표 열 너비는 마우스로 드래그해 조절할 수 있습니다.

- CONFIG의 **설정명**을 바꾸면, 그 이름을 참조하는 모든 서브시퀀스 Step의 `설정명(비교대상ID)`
  칸도 같이 바꿔야 합니다 - 안 바꾸면 그 조건은 CONFIG에서 못 찾아 경고가 뜨고 "조건 없음"으로
  처리됩니다.
- **ID**는 현재 실제 데이터가 전부 이름으로 참조하고 있어서 당장 바꿔도 안전하지만, 앞으로
  ID로 참조하는 조건을 추가하면 그때부터는 이름과 마찬가지로 신경 써야 합니다.

## 8. 자주 하는 실수

- **`&` 개수 불일치** - 태그 4개를 적어놓고 연산자/대상은 1개만 적는 실수. 콘솔 경고 + 토스트로 알려줍니다.
- **CONFIG 오타** - id/설정명 둘 다에 없고 숫자도 아니면 오타로 간주해 경고합니다(옵션 `?` 여부와 무관).
- **BIT 조건에서 대상 칸을 비움** - `&`로 여러 조건을 묶을 때 개수가 안 맞아 전체 조건이 깨집니다. `-` 같은 자리표시자를 채우세요.
- **Alarm Goto/Next Step 오타(존재하지 않는 Step No)** - 콘솔 경고 + 토스트를 띄우고, 평소처럼 다음 Step으로 진행하는 것으로 안전하게 대체합니다(무한 대기·크래시 없음).
- **`Alarm Goto`를 채워야 하는데 `Alarm Seq.`도 같이 채워둔 경우** - 실행에는 지장 없지만(Alarm Goto가 우선), 헷갈리지 않게 Alarm Goto만 쓰는 Step은 `Alarm Seq.`를 비워두는 것을 권장합니다(에러사항 기록 여부도 이 값 기준입니다 - 6장 참고).

## 9. 새 조건/분기를 추가할 때 체크리스트

1. 이 Step이 **알람**(문제 상황 대응)인가, **정상 분기/반복**(Option, 반복문 등)인가?
   - 알람이면: `Alarm Seq.` 채우고 `Alarm Goto`는 비움.
   - 분기/반복이면: `Alarm Goto`를 채우고, 필요 없으면 `Alarm Seq.`는 비워둠(에러사항에 안 남도록).
2. 조건이 참일 때 갈 곳이 "무조건 다음 줄"이 아니면 `Next Step`을 채운다.
3. `{side}`가 필요한 태그/설정명인지 확인한다(측별 값이면 반드시 넣는다).
4. 조건 3열(`Alarm Monitoring`/`비교연산자`/`설정명(비교대상ID)`)의 `&` 개수가 서로 맞는지 확인한다.
5. `Remarks`에 이 Step이 하는 일을 간단히 적어둔다(특히 분기/반복처럼 특수한 Step).
6. 불러오기 후 콘솔/토스트에 경고가 없는지 확인한다.

## 10. 예외: 용기교체(CC) 밸브 개폐 타이밍 문법 (`CylReplace_v1`)

`CylReplace_v1`만 다른 서브시퀀스와 구조가 다릅니다 - 6개 화면(실린더 확인~Auto Guard Close
확인) 전체의 순서·밸브 상태를 **진입화면 하나("실린더 확인")에만** 있는 이 데이터 한 파일로
규정하고, 나머지 5화면은 자기 단계에 해당하는 밸브 상태만 읽기 전용으로 조회합니다(자세한
구조는 `docs/GMS_AUTO_SEQUENCE_HANDOFF.md` 11.6절). 화면 전환은 다른 서브시퀀스처럼
타이머로 자동 진행하지 않고 지금처럼 "확인" 버튼 클릭으로 이루어지므로, `Time (Sec)`/
`Next Step`/`Alarm Goto` 등은 채워져 있어도 실제로는 쓰이지 않습니다.

밸브 상태는 화면에 글자로 표시되지 않고 **SVG 배관도의 실제 밸브 아이콘**에 반영됩니다. 밸브
열 값은 보통의 `O`/`C` 외에 다음 문법을 추가로 지원합니다.

```
PIV: O          ← 화면 진입 즉시 Open
PGII_A: O+2     ← 화면 진입 2초 뒤에 Open
PGI_A: O+4      ← 화면 진입 4초 뒤에 Open
```

`O+n`/`C+n`(n=초)으로 쓰면 그 밸브만 n초 뒤에 순차로 개폐됩니다 - 같은 Step 안 여러 밸브를
동시에가 아니라 시간차를 두고 열고/닫고 싶을 때 씁니다(예: Step2 "Valve Open 확인"이
PIV→PGII→PGI를 2초 간격으로 여는 것). 숫자만 바꾸면 타이밍이 바뀌고, 밸브 열을 새로
추가(엑셀에 새 열 이름 추가)하면 코드 수정 없이 그 Step에 자동으로 반영됩니다.

## 11. 자동 백업 (`data/gmsSubSequenceBackups/`)

서브시퀀스를 "불러오기"로 저장할 때마다, **덮어쓰기 직전의 이전 버전**이
`data/gmsSubSequenceBackups/<id>/<id>_<시각>.json`(+같은 이름의 `.xlsx`)으로 자동 저장됩니다.
문제가 생기면 이 폴더에서 이전 버전을 그대로 다시 불러와 되돌릴 수 있습니다.

**주의할 점**: 이 백업은 "저장이 실제로 일어날 때"만 만들어집니다 - 파일이 **처음** 만들어질
때는(그 전에 같은 id 파일이 없었으므로) 백업할 대상 자체가 없어 폴더가 생기지 않습니다. 즉
`data/gmsSubSequenceBackups/`에 어떤 서브시퀀스 폴더가 아직 없다면 "그 서브시퀀스를 지금까지
한 번도 엑셀로 불러오기(저장)한 적이 없다"는 뜻이지 오류가 아닙니다 - 처음 한 번 편집해서
불러오기하면 그 순간부터 백업이 쌓이기 시작합니다.
